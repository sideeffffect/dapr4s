## Source facts (file:line at the tags above)

- Two error families. Legacy `messages.APIError` (`pkg/messages/api_error.go:85-104`): HTTP body
  `{"errorCode","message"}`; gRPC `status.New(code, msg)` with NO details. Kit errors (`dapr/kit errors/errors.go:156-245`):
  HTTP body adds `details[]` with a `google.rpc.ErrorInfo` (`reason`, `domain: dapr.io`, `metadata`); gRPC carries the
  same details. `apierrors.Basic(...)` (`pkg/api/errors/errors.go:26`) uses an empty tag and reason = the ERR_ code.
- Not-found / not-configured codes: predefined.go `ErrStateStoreNotFound`/`...NotConfigured` (kit, `state.go:39/59`),
  `ErrPubsubNotFound` (kit `pubsub.go:108`, 404), `ErrSecretStoreNotFound` (82, 401), `ErrSecretStoreNotConfigured` (81),
  `ErrConfigurationStoreNotFound` (http.go:716, grpc.go:1260 Basic), `ErrLockStoreNotFound` (119),
  `ErrLockStoreNotConfigured` (lock.go:131), `ErrCryptoProviderNotFound` (89) / `ErrCryptoProvidersNotConfigured` (88,
  gRPC Internal), `ErrConversationNotFound` (`universal/conversation.go:57`). `ErrWorkflowComponentNotFound` (129) is
  defined but never used in 1.17. Output bindings have no dedicated code: `ERR_INVOKE_OUTPUT_BINDING` wrapping
  `runtime/processor/binding/send.go:217` "couldn't find output binding %s".
- Permission: `ERR_PERMISSION_DENIED` 403/PermissionDenied (secret scopes, `universal/secrets.go:36`);
  `ERR_PUBSUB_FORBIDDEN` 403, kit reason `DAPR_PUBSUB_FORBIDDEN` (`pubsub.go:87`); invoke ACL: callee returns gRPC
  PermissionDenied, caller HTTP API answers 403 `ERR_DIRECT_INVOKE` "failed to invoke, id: X, err: rpc error: code =
  PermissionDenied desc = access control policy has denied access ..." (directmessaging.go:168-176, acl.go:163).
- Invoke: `ErrDirectInvoke` "failed to invoke, id: %s, err: %v" (predefined.go:71). mDNS: "couldn't find service: %s"
  (mdns.go:572) or "timeout waiting for address for app id %s" (mdns.go:524). When the app answers, the HTTP invoke API
  passes status, body, content type and headers through unchanged (directmessaging.go:217-228, 341-349); the error
  range is `< 200 || > 399`.
- Java SDK 1.17.2: `invokeMethod` is the only HTTP call (DaprClientImpl.java:609-650), everything else gRPC.
  `DaprException.propagate(StatusRuntimeException)`: errorCode = gRPC status name (`INVALID_ARGUMENT`), NOT the ERR_
  code; message built as "CODE: msg"; payload = `google.rpc.Status` bytes. `DaprHttp.createResponse` throws for any
  status outside 2xx (3xx included), parses `{"errorCode","message"}` into the exception, keeps the body as payload,
  drops response headers on success.
- @dapr/dapr 3.18.0: `HTTPClient.execute` rejects statuses outside 200–399 with `new Error(JSON.stringify({error:
  statusText, error_msg: body, status}))`; `pubsub.publish`, `pubsub.publishBulk`, `state.save`, `state.delete` resolve
  `{error}` instead of rejecting; configuration and crypto are gRPC-only (Connect `ConnectError`: numeric `code`,
  `rawMessage`, decoded `details`).
