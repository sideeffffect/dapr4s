## Introduction

Capture checking can be enabled by the language import:

```scala
import language.experimental.captureChecking
```

A motivating example — `usingLogFile` pattern:

```scala
def usingLogFile[T](op: FileOutputStream => T): T =
  val logFile = FileOutputStream("log")
  val result = op(logFile)
  logFile.close()
  result
```

The problem: one can undermine it by passing an operation that performs logging after termination:

```scala
val later = usingLogFile { file => () => file.write(0) }
later() // crash — file already closed
```

With capture checking, declare:

```scala
def usingLogFile[T](op: FileOutputStream^ => T): T = ...
```

Now `later` is rejected statically:

```
Found:    (f: java.io.FileOutputStream^'s1) ->'s2 () ->{f} Unit
Required: java.io.FileOutputStream^ => () ->'s3 Unit
Note that capability f cannot be included in outer capture set 's3.
```

Capture checking distinguishes safe uses (e.g., `List.map` with the file) from unsafe ones (e.g., `LzyList.map` which retains the file across lazy evaluation).

Applications: checked exceptions, effect polymorphism, "what color is your function?" problem, region-based allocation, reasoning about memory-location capabilities.

## Capabilities and Capturing Types

Capturing types have the form `T^{c₁, ..., cᵢ}`. A _capture set_ `{c₁, ..., cᵢ}` consists of references to capabilities.

An _object capability_ is syntactically a method- or class-parameter, a local variable, or the `this` of an enclosing class. The type of a capability must be a capturing type with a non-empty capture set. Such variables are _tracked_.

Every capability derives its authority from a more sweeping capability. The recursion stops with the _universal capability_ `any`. `T^` is shorthand for `T^{any}`.

Example:

```scala
class FileSystem

class Logger(fs: FileSystem^):
  def log(s: String): Unit = ...

def test(fs: FileSystem^) =
  val l: Logger^{fs} = Logger(fs)
  val xs: LzyList[Int]^{l} =
    LzyList.from(1).map { i =>
      l.log(s"computing elem # $i")
      i * i
    }
  xs
```

## Function Types

- `A => B` — impure function, alias for `A ->{any} B`, can capture arbitrary capabilities
- `A -> B` — pure function, cannot capture any capabilities
- `A ->{c, d} B` — function that can capture `c` and `d` only (shorthand for `(A -> B)^{c, d}`)

`A ?=> B` is impure context function; `A ?-> B` is its pure complement.

`->` and `?->` are soft keywords in type positions; `Map("x" -> 1)` in terms is unaffected.

Methods never capture anything directly — references to capabilities in a method count toward the enclosing object's capture set.

## By-Name Parameter Types

- `def f(x: => Int)` — actual argument can use arbitrary capabilities
- `def f(x: -> Int)` — actual argument must be pure
- `def f(x: ->{c} Int)` — actual argument may use only capability `c`

## Lazy Vals

Lazy vals have two distinct capture sets:

1. **Initializer's capture set** — capabilities used by the initialization code
2. **Result's capture set** — capabilities retained by the lazy val's value

Accessing a lazy val requires the initializer's capture set, even if the result is pure:

```scala
def example(console: Console^) =
  lazy val x: () -> String =
    console.println("Computing x")
    () => "Hello, World!"

  val fun: () ->{console} String = () => x()   // ok
  val fun2: () -> String = () => x()            // error: x captures console
```

For member lazy vals, accessing through a qualifier charges the qualifier to the capture set (same as a parameterless method):

```scala
def client(c: Container^): Unit =
  val f1: () -> String = () => c.lazyMember     // error
  val f2: () ->{c} String = () => c.lazyMember  // ok
```

## Subtyping and Subcapturing

- Pure types are subtypes of capturing types: `T <: T^C` for any `T`, `C`
- Smaller capture sets produce subtypes: `T₁^C₁ <: T₂^C₂` if `C₁ <: C₂` and `T₁ <: T₂`

A subcapturing relation `C₁ <: C₂` holds if `C₂` accounts for every element `c` in `C₁`:
- `c ∈ C₂`, or
- `c` refers to a parameter of class `Cls` and `C₂` contains `Cls.this`, or
- `c`'s type has capture set `C` and `C₂` accounts for every element of `C`

The root capability `{any}` covers every capture set.

When a local variable `l` with capture set `{fs}` would appear in a result type outside its scope, it is widened via _avoidance_ to the smallest supertype not mentioning `l` — in this case `{fs}`.

## Capability Classes

Classes can extend `SharedCapability` to indicate their values are always capabilities. A type extending `SharedCapability` always comes with a capture set; without explicit annotation, the capture set is `{any}`.

```scala
import caps.SharedCapability

class FileSystem extends SharedCapability

class Logger(using FileSystem):
  def log(s: String): Unit = ???

def test(using fs: FileSystem) =
  val l: Logger^{fs} = Logger()
```

## Escape Checking

Capabilities follow the usual scoping discipline: capture sets can only contain capabilities visible at the point where the set is defined.

Trying to assign a closure with a local capability to a global variable also fails:

```scala
var loophole: () => Unit = () => ()
usingLogFile { f =>
  loophole = () => f.write(0) // error: f not visible outside usingLogFile
}
```

### Monotonicity Rule

In a class `C` with a field `f`, the capture set `{this}` covers the capture set `{this.f}` as well as the capture set of any application of `this.f` to pure arguments.
