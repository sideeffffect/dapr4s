# Capture Checking of Classes

## Introduction

The principles for capture checking closures also apply to classes.

```scala
class Logger(using fs: FileSystem):
  def log(s: String): Unit = ...

def test(xfs: FileSystem): Logger^{xfs} =
  Logger(using xfs)
```

A capability meant only for the constructor (not retained as a field) can be annotated `@constructorOnly`:

```scala
import scala.annotation.constructorOnly

class NullLogger(using @constructorOnly fs: FileSystem):
  // fs used only during construction
def test2(using fs: FileSystem): NullLogger = NullLogger() // OK — no fs in type
```

The captured references of a class include _local capabilities_ (defined outside the class, referenced from its body) and _argument capabilities_ (passed as constructor parameters). Local capabilities are inherited by subclasses.

## Capture Set of This

The capture set of `this` is inferred unless declared via a self-type annotation:

```scala
class C:
  self: D^{a, b} => ...
```

Constraints:
- `this` includes all captured references of the class
- `this` is a subtype of `this` of each parent class
- `this` must satisfy all usage constraints

For non-open, non-abstract classes all subclasses are known, so the checker can precisely infer self-type.
For traits, abstract classes, and `open` classes, the checker conservatively assumes `this` can capture arbitrary capabilities (`any`).

```scala
class A:
  def fn: A = this   // ok — concrete class

trait B:
  def fn: B = this   // error — trait: this has type B^
  def fn2: B^ = this // ok

abstract class C:
  def fn: C = this   // error
  def fn2: C^ = this // ok

sealed abstract class D:
  def fn: D = this   // ok — sealed, all subclasses known
```

### Inheritance

The self-type capture set serves as an upper bound for extending classes:

```scala
abstract class Sub extends Root:
  this: Sub^{a, b} => // ok, refinement {a, b} <: {any}

class SubGood extends Sub:
  val fld: AnyRef^{a} = a // ok, {a} included in {a, b}

class SubBad extends Sub: // error: {io} not admitted by Sub^{a, b}
  val fld: IO^{io} = io
```

Higher in the hierarchy → more permissive (impure); lower → more restrictive (pure). `AnyRef`/`Object` conceptually has the universal capability.

## Capture Tunneling

When a type variable is instantiated to a capturing type, the capture is not propagated beyond the generic constructor application. It "tunnels through" and reappears on access.

```scala
class Pair[+A, +B](x: A, y: B):
  def fst: A = x
  def snd: B = y

def x: Int ->{ct} String
def y: Logger^{fs}
def p: Pair[Int ->{ct} String, Logger^{fs}] = Pair(x, y)
// p has empty capture set at the outside
val f: () ->{ct} Int ->{ct} String = () => p.fst // ct reappears on access
```

This principle is important for making capture checking practical: references "tunnel through" generic instantiations.

## Captures of New

The capture set of `C(args)` consists of:

**Local elements:**
- All capabilities passed in parameters
- All capabilities in the types of class fields

**External elements:** All capabilities from outside the class referenced by a method of the class.

External capabilities can be declared explicitly with a `uses` clause (required for classes visible across compilation units):

```scala
class C(x: () => Unit) uses out, io:
  val f: File^{io} = File()
  def g() =
    out.println("one")
    f.write("two")
    x()
```

If `C` extends `Capability`, `any` is always added to the capture set of `new C`. Similarly if the class has fields that capture `any`.

## Captures due to Class Initialization

Capabilities accessed during initialization are separate from what the created instance retains. A factory function `() => D()` charges capabilities used during `D`'s initialization:

```scala
class D():
  val str: String =
    out.println("str was initialized")
    "abc"

val _: () ->{out} D = () => D()
```

Initialization capabilities can be declared with `uses ... initially`:

```scala
class D() uses out initially:
  val str: String = ...  // out used during init

class D() uses out initially, out:  // used during init AND retained afterwards
  val str: String = ...
  def print() = out.println(str)
```

Syntax: `uses` clause follows `extends` and `derives`.

## A Larger Example: Lazy Lists

```scala
trait LzyList[+A]:
  def isEmpty: Boolean
  def head: A
  def tail: LzyList[A]^{this}  // tail can capture same references as whole list
```

`LzyCons` retains the tail function, so it captures impure closures:

```scala
final class LzyCons[+A](hd: A, tl: () => LzyList[A]^) extends LzyList[A]:
  // memoized tail via private mutable cache
  def tail: LzyList[A]^{this} = force
```

Key insight from the example:

- `map`, `filter` result capture both the list and the function (since lazy, function is retained)
- If the mapping function is pure, it does not appear in the result capture set — natural _effect polymorphism_
- Pure strict lists require no capture annotations at all; lazy lists need them only where effects are delayed
- This is a "sweet spot" property of the approach vs. prior techniques

Two annotation-free sweet spots:
1. Strict lists in side-effecting code
2. Lazy lists in purely functional code

Capture annotations only arise where delayed effects are involved.
