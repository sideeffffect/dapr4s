# Safe Mode

> Source: https://raw.githubusercontent.com/scala/scala3/main/docs/_docs/reference/experimental/capture-checking/safe.md
> Collected: 2026-05-01
> Published: Unknown

Safe mode is a restricted language subset built on capture checking that prevents tracked capabilities from being lost. It is designed to make agent-generated code safer by disallowing potentially dangerous features.

## Key Restrictions

Safe mode enforces six main limitations:

1. **No unsafe type operations** — No unchecked type casts or pattern matches
2. **No unsafe modules** — Blocks access to `caps.unsafe` features
3. **No unchecked annotations** — Prevents `@unchecked` and related markers
4. **No reflection** — No access to runtime reflection
5. **Effect tracking required** — Must compile with capture checking enabled
6. **Safe library access only** — Can only call global objects that are themselves safely implemented

## Escape Mechanisms

The `@assumeSafe` annotation allows library developers to mark components as safe even when compiled outside safe mode. This is useful for libraries that use untracked mutations (like caches) in ways that don't affect external behavior.

Conversely, `@rejectSafe` prevents specific members from being accessible in safe mode.

## Exception Handling

Safe mode permits exceptions. Rather than tracking all exception types through capabilities, the design relies on wrapping untrusted code calls in `Try` blocks to contain thrown exceptions as values.

## Use Cases

Projects like TACIT employ safe mode to validate and type-check AI agent-submitted code before execution, ensuring capabilities flow through explicit typed APIs rather than being lost to unsafe language features.
