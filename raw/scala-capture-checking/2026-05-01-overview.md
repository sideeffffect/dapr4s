Tracked capabilities are supported under Scala's capture checking extension:

```scala
import language.experimental.captureChecking
```

Some more features (mutable data structures, alias control) require:

```scala
import language.experimental.separationChecking
```

Both extensions are experimental. Capture checking is quite mature and expected to be stabilized soon. Separation checking is still more fluid.

## Capabilities

Informally, a capability is a value "of interest". For instance, a file handle, an access permission token, or a mutable data structure all make sense as capabilities. Often capabilities are associated with effects.

One can designate a value as a capability by making the type of the value extend directly or indirectly the standard trait `Capability`. For instance:

```scala
class File(path: String) extends ExclusiveCapability
```

Here, `ExclusiveCapability` is a subtrait of `Capability` that prevents concurrent accesses.

## Capability Tracking

Capabilities in Scala 3 are *tracked*. We record in a type which capabilities can be accessed by values of that type. We write `A^{c}` for the type of values of type `A` that can access the capability `c`.

```scala
val out: File^ = new File("~/some/bits")
val lg: Logger^{out} = new Logger(out)
```

`lg` has type `Logger^{out}`, indicating it captures file `out`. This is a _capturing type_.

Generally, `A^{c₁, ..., cₙ}` stands for instances that retain capabilities `c₁, ..., cₙ`.
If class `A` does not extend `Capability`, then `A` alone stands for instances that retain no capabilities — `A` is _pure_, equivalent to `A^{}`.
`A^{any}`, or shorter `A^`, means instances that can retain arbitrary capabilities.

Values of capturing types are themselves considered capabilities.

Capability sets induce a subtyping relation, where smaller sets lead to smaller types:
```
A  <:  A^{lg}  <:  A^{out}  <:  A^{out, f}  <:  A^
```

## Function Types

The function type `A -> B` is considered pure (cannot retain any capability). Shorthands:

```scala
A ->{c₁, ..., cₙ} B   =  (A -> B)^{c₁, ..., cₙ}
             A => B   =  A ->{any} B
```

A function captures any capabilities accessed by its body:

```scala
val next: Int ->{lg} Int = (x: Int) =>
  lg.log(s"called with parameter $x")
  x + 1
```

Methods don't have expressible types and don't have tracked capability sets; the capability set is associated with the enclosing object.

## Lifetimes

Tracking capabilities in types allows controlling their lifetimes. For example:

```scala
def logged[T](op: Logger^ => T): T =
  val f = new File("logfile")
  val l: Logger^{f} = new Logger(f)
  val result = op(l)
  f.close()
  result
```

This definition prevents leaking the logger `l` in the result. The following is rejected:

```scala
val bad = logged { l =>
  () => l.log("too late!")   // compile error
}
```

The type parameter `T` must be independent of the logger's identity — violated here because the result type would be `() ->{l} Unit`.

## Implicit Capability Passing

Capabilities are often passed as implicit parameters via `using` clauses:

```scala
def processData(using Async): Data =
  val file = new File("~/some/path")
  readDataEventually(file)
```

The capability `Async` is passed implicitly without needing to be named at each call site.

## Mutation

Mutable variables and mutable data structures are also capabilities.

```scala
def counterOps =
  var counter: Int = 0
  val incr = () => counter += 1
  val current = () => counter
  (incr, current)
```

The function `incr` has type `() ->{counter} Unit`. We distinguish read and write accesses: a read access charges `m.rd`, while a write access charges the full capability `m`.

Mutable data structures extend trait `Mutable`:

```scala
abstract class Buffer[T] extends Mutable {
  update def append(elem: T): Unit
  def apply(pos: Int): T
  def size: Int
}
```

The `update` modifier marks methods that change the state. A reference of type `Buffer` only allows regular methods; `Buffer^` also allows update methods.

## Global Capabilities

With tracked capabilities, global capabilities can be allowed since access is controlled through types:

```scala
object Console extends SharedCapability:
  val in: File = new File("stdin")
  val out: File = new File("stdout")

object SimpleLogger uses Console:
  def log(str: String): Unit = Console.out.println(str)
```

A global object that refers to `Console` declares that dependency in a `uses` clause.

## Summary

Scala 3's capabilities are more convenient (using `using` clauses for implicit passing, global capabilities reducing wiring) and more expressive (tracked types describe and constrain computational effects, read-only vs. update distinction, ensuring updates only to unshared references).
